> 맥락: 3단 GLB 스왑 시 TentSwapCo의 스케일 팝(6%)이 눈에 띈다는 지적.
> 이후 "가스 공사 에셋에 생성해서 넣어놨다"로 CampTentBody/BodyOpen/Door GLB 3종 전달
### 조작 내역
- 구조 변경: 본체(창닫) + 본체(창열) + **분리된 문짝** 3부품.
  본체는 진입 때 건드리지 않으므로 팝이 생기지 않는다. 환기 때만 본체 1회 교체(바람 VFX가 순간을 덮는다)
- 감량: 3종 각 57MB → 5.1~5.3MB (v3.1 HD라 삼각형 193만 → 15만, 텍스처 2048)
- 방향 실측: 모델마다 베이크 축이 달랐다 — Body=yaw 270, BodyOpen=yaw 0 (Door는 회전 없음)
- 정렬: 폭·바닥·"문 구간 최전방 천 표면 z=3.469" 3축 기준으로 Body↔BodyOpen 일치
- 문짝 배치: 텍스처 UV로 검은 출입구 정점을 찾아 로컬 bbox를 구하고, 그 월드 좌표에 맞춰 스케일·정렬 (폭 1.70 높이 2.26)
- **문짝 메시를 좌우로 분할**(td_L/td_R.asset): 원본은 통짜라 가로 축소 시 가운데로 빨려들어간다.
  삼각형 중심 x로 좌우를 갈라 각 조각의 원점을 바깥 기둥으로 옮겨, 각자 자기 기둥 쪽으로 접히게 함
- 색 보정: 생성마다 albedo 밝기가 달라(캔버스 평균 밝기 122~178, 최대 29% 차이) 기존 돔 텐트(144.2) 기준으로 정규화.
  Body 0.916 / BodyOpen 0.811 / Door는 본체와 정확히 맞추려 채널별 (0.872, 0.834, 0.970)
- 코드: `tentBody/tentBodyOpen/doorL/doorR` + `DoorApply/DoorSetCo` 신설. CampTentInitState가 이 구조를 1순위로,
  없으면 3단 GLB → 절차 텐트 → 기존 GLB 순으로 폴백
### 검증
- 컴파일 Error 0건
- 에디터 스냅 8장: 방향 4종 비교 ×2, 문짝 정렬 3회 반복, 닫힘/열림/환기 상태
- 플레이 검증: 시작 tentBody=ON doorL/R=ON doorW0=1.96 → 진입 중 doorL scale.x=0.20 yaw=22 (본체는 그대로) → 실내 진입 성공
- 환기 호출 후 tentBody=off tentBodyOpen=ON, 창 덮개 말려 올라간 상태·데크 유지 확인
### 실패와 수정
- Tripo API가 크레딧 부족(code 2010)으로 거절 → 웹 크레딧과 API 크레딧이 별도 지갑. 동현님이 웹에서 직접 생성해 전달
- BodyOpen을 Body와 같은 yaw 270으로 뒀다가 측면이 정면으로 왔다. 4방향 비교로 yaw 0이 정답(문+데크 동시 정면)임을 확인
- bbox z최대로 정렬했더니 Body는 데크 앞끝, Open은 텐트 뒤끝이 기준이 되어 어긋났다 → "문 앞 천 표면 z"로 기준 통일
- 창의 촘촘한 방충망이 텍스처 굽기에서 검은 노이즈로 뭉갬 → 이미지를 매끈한 단색 판으로 바꿔 재생성(동현님)
